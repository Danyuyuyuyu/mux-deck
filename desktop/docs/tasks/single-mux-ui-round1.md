## 目标与基线

把当前单个封装页改为视频摘要、分组内容清单、紧凑设置与固定状态区，加入视频、ASS、字体目录拖入。用户由其他 agent 实现；本聊天的技术负责人负责派发、审查与最终验收。各任务完成报告经用户转交。

基线分支为 `v2/avalonia-rewrite`，提交为 `0422069f8f05dac54999c76a4229f2cc8947911d`；规划时工作树干净。执行者开始时重新查看状态，保留其他人的改动。仓库 `desktop/AGENTS.md`、`docs/agents/skeleton.md`、`migration.md`、`verification.md` 继续适用。

桌面上的 `Mux_Deck_V2_Single_Mux_UI_Redesign.md` 是设计参考。本任务按当前用户授权收窄为第一轮，设计参考中的源轨道选择、源附件保留和独立字体检查留到后续。

## 本轮产品合同

### 封装边界

- 使用现有 Core：一个源视频、1–2 条启用的 UTF-8 ASS、显式字体目录和独立输出目录。
- 全部源视频及音轨固定保留；源字幕与附件固定移除。主表清楚显示策略，不提供可操作的源保留复选框。
- 继续使用 SC/TC 两个槽位与固定 `zh-Hans` / `zh-Hant`；外加字幕支持暂时禁用、替换、移除及已有名称/default/forced 编辑。所有外加字幕禁用时不能开始。
- 新增/移除槽位沿用现有 SC/TC 默认规则；同槽替换保留名称和显式旗标；暂时禁用/重新启用保留旗标。本轮不新增全局默认轨单选规则。
- 输出默认名保持 `<sourceStem>.muxed.mkv`；独立目录、拒绝覆盖、取消与 QC 均保持现有规则。
- Core、进程模块、诊断白名单、包版本和 v1 代码不在本轮修改范围。

### 页面与信息

- Tab 调整为“封装 / 字体附件”；开发模式额外显示“日志”。Release 的结果详情仍可查看、复制诊断以及定位任务日志。
- 顶部显示视频文件名和已探测的尺寸、编码、时长、轨道数；完整路径可在详情中查看和复制。未知字段省略或显示未取得，不从扩展名猜容器名称。
- “轨道与内容”使用源内容、外加内容两个分组。列表不逐项铺开源附件，只显示附件数及固定移除策略，详情可展开。
- 常驻列优先使用策略/加入、类型、名称、格式、语言、默认、操作；来源由分组表达，强制旗标在 Inspector 中编辑和查看。
- Inspector 可展开/关闭；小窗口以折叠或下方详情保持主表可读。选择、勾选与行按钮的交互互不误触。
- 字体目录、输出目录和输出文件名集中到封装页下部。字体页本轮呈现目录与处理说明，不显示虚构字体清单或“检查通过”。
- 底部固定状态和主操作，不常驻原始日志。准备时使用“输入已齐全，封装时检查”；运行时展示真实阶段与不定进度；成功只由 Core 结果确定。
- 状态覆盖无视频、探测中/失败、输入不全、运行、正在取消、取消、失败、成功及成功附提示。成功/失败详情保留 `Checks`、`Warnings` 和原始 `Error`；主区不把完整工具输出当标题，不基于日志关键词推断失败原因。
- 修改任务参数后区分当前草稿和上次结果，避免新配置沿用旧成功状态。切 Tab、选择查看某行、展开详情不会让草稿失效。
- 成功提供“打开文件位置 / 再次封装”；再次封装仍检查目标冲突，不自动覆盖或改名。输入选择、目录选择、复制、打开失败均有可见提示。

### 拖入与文件选择合同

| 接收区 | 接受内容 | 行为与失败方式 |
|---|---|---|
| 视频摘要 | 单个 MKV/MP4 文件 | 初次设置视频；已有视频时提示替换，允许撤销拖入/取消确认；保留字幕和设置，清掉旧源探测及行选择，重新探测 |
| 外加内容 | 1–2 个 ASS 文件 | 通过小型分配界面明确指定 SC/TC；已有槽位替换须明示；取消不改状态；不靠文件名猜语言 |
| 字体目录 | 单个本地文件夹 | 设置目录；不递归扫描或自动检查，显示封装时检查 |

- 文件选择按钮与拖入最终走同一套输入接纳规则。MKV/MP4 为本轮受支持并验收的输入；修改当前过宽的选择器过滤器，与提示一致。
- 拖入以本地文件/文件夹数据为准，支持中文、空格和大写扩展名。URL、纯文本路径、错误类型、超过数量、重复 ASS 和不存在的路径给出可见原因，保留原输入。
- 一个拖入操作先验证完整候选及 SC/TC 分配，再一次提交；混合视频+ASS、两个视频、ASS 超量、同一路径分到两个槽位等整体拒绝，避免部分写入。
- 校验字幕重复时包含已有槽位；允许对同一槽位进行同路径的无害操作。路径按 Windows 绝对路径及大小写规则比较，本轮不处理硬链接/符号链接身份去重。
- 拖入悬停高亮对应区域并说明将执行的动作；拒绝时无可接受高亮；离开/取消/处理完成清理高亮。
- 运行、取消清理和关闭等待期间禁止改输入；弹窗/选择器返回后再次核验 `CanEdit`。导航、结果详情及日志查看仍可用。
- 设置输出目录继续通过选择按钮；不做全窗口混合文件智能导入或自由多字幕列表。

## 执行顺序和文件归属

同一共享工作区按 A → 审查 → B → 审查 → C → 最终验收串行执行。实现者可反馈具体阻碍及替代方案；涉及范围变化先交由负责人裁决。各 agent 提交前查看 diff，不重置或清理其他人的文件，不自动提交或推送。

| 任务 | 建议模型 | 主责与文件归属 | 出口条件 |
|---|---|---|---|
| A：状态与输入接纳 | gpt-6.1-sol / high | `SingleMuxViewModel.cs`、`TrackRowViewModel.cs`；必要的 Desktop 输入接纳类型；独立行为检查及 `Program.cs` 最小接线；`skeleton.md` 对应状态说明 | 现有 UI 仍构建可用，后续视图有明确可复用接口，行为检查通过 |
| B：界面与拖入 | gpt-6.1-sol / high | A 审查后的 Views、`App.axaml`、必要的展示接线及平台动作帮助类；相关 UI smoke；同步受影响的架构/操作说明 | 页面、实际拖入、原生选择器、结果动作可用，截图及真实 UI 路径有证据 |
| C：独立审查与验收 | gpt-6.1-sol / high | 只读审查实现与执行验证，报告缺陷；修复回派 A/B | 按本文件逐项记录通过、失败、未覆盖与证据 |

任务 B 前须处理旧 `VideoInput` 文本框 smoke 合同：用真实新入口与绑定行为替换验收，并同步 `skeleton.md`。保留 `MainWindowViewModel` 的已有转发属性；禁止用不可见假文本框维持旧测试。

第一轮新增行为证据以 A/B 实际报告为准，不能引用旧 26/26、10/10 或 Core 报告作为本轮通过。

## 最终验收矩阵

| 范围 | 必须观察到的行为 |
|---|---|
| 布局 | 空态、带多条源轨/附件与 SC+TC、运行、成功附提示、失败；1280×900 和 1040×760 逻辑尺寸可读，无按钮或焦点遮挡；Windows 125%/150% 实测记录显示设置与可用工作区，小工作区必要时调整最小尺寸 |
| 输入 | 视频更换后旧探测迟到不覆盖；选择器取消、拖入取消无状态变化；中文/空格路径和大写扩展名正确 |
| 拖入 | 分别接受视频、ASS、字体文件夹；拒绝混合、超量、重复、错误类型、非本地数据；原生 Explorer 到应用的真实拖入检查，不以调用接纳方法替代 |
| 字幕 | 禁用不丢路径/属性，移除清空槽位；提交快照仅含启用 ASS；全部禁用不可开始；替换不改名称与显式旗标 |
| 任务生命周期 | 运行与取消清理锁定输入；弹窗迟到不能改任务；切页保留状态；关闭等待工具退出及探测结束 |
| 状态与结果 | 输入齐全不冒充预检通过；无虚构百分比；提示与失败分开；配置变更标记上次结果；打开位置、复制与诊断详情可用，目标已存在时仍拒绝覆盖 |
| 回归 | Release 构建、常规 Smoke 与相关行为检查；真实 UI 走现有 Core 完成单 ASS、SC+TC、TC-only（按新增影响选取最小 fixture），核对实际新 UI 提交与产物，不重复完整电影重放 |

构建及运行命令沿用 `desktop/README.md`；外部工具运行串行、素材隔离到本次 `desktop/artifacts/` 子目录。Core 未改时不强制重跑全部真实 Core 回归；若发现必须修改 Core，先报告范围变化，由负责人重新确定验证。

Headless 布局截图和行为检查不能证明原生拖入、选择器、资源管理器打开或 Windows DPI 通过。无法操作真实桌面时将这些项列为“待人工”，由用户按清单执行并反馈；第一轮最终结论保留该限制。

## 完成报告与审查

每项任务返回：变更文件及职责；公开属性/方法/类型；完成的验收场景及命令结果；截图/报告绝对路径；未覆盖项与具体阻碍；任务范围偏离及原因。可用 Git diff 作为代码证据，暂不要求提交。

负责人检查代码与运行证据，给出通过、需修复或待验收结论；未通过时发最小修复任务。仅在相关自动验证与上述人工项有结果后记录第一轮完整通过；阶段进度的权威位置仍是 `docs/agents/migration.md`。

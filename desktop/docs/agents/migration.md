# 开发流程与阶段验收

v2 重新实现主程序，按单个封装、可靠性、批量、扩展能力推进。旧版用于理解已存在的业务行为，阶段范围以本文和当前用户任务为准。

## 当前进度

- 阶段一实现已落位：单个 MKV/MP4、1–2 条 UTF-8 ASS、固定 AssFontSubset/PyFontTools 子集、独立输出、逐轨元数据和源 A/V QC、源字幕/附件替换、失败/取消不发布成品，以及真实单任务 UI。
- 真实工具链 121/121 的最新报告于 2026-10-10 通过，已包含严格 ASS transport 参考比较，见[阶段一集成报告](../../artifacts/phase1/20261010-015647-daefe8254a624279bdb71f726b161b95/report.json)。真实 UI 10/10 的[历史截图](../../artifacts/phase1/20261009-113607-f1ca9f2ec2694a72aa06fbdc0a31deb3/real-ui-success.png)来自 2026-10-09；最新自动验收数字见[验证要求](verification.md#当前自动化能力)。
- 完整电影重放在更换为同一 MKVToolNix transport 参考后，于 2026-10-10 通过 9/9，见[真实电影报告](../../artifacts/warning-policy/real-e223f0011b774942bf40123b7b1c76a3/report.json)。旧[失败报告](../../artifacts/warning-policy/real-52d8443120a74073b2438784789bc798/report.json)定位到四条 Comment 移至 `[Events]` 的 `Format` 行后；Dialogue 顺序/内容、Script Info、AFS 映射和 Styles 相同。新机制用每条修正 ASS 的同工具封装/提取参考全文比较修复了该 transport 差异。原生文件选择器与真实播放器播放仍待人工检查。批量队列尚未开始，仍为占位。
- 已发现阶段二 P2 可靠性待处理：`Process.Start()` 到 Windows Job Object 归属之间不是原子操作。当前测试覆盖已归属后的同步 AFS 取消和父进程退出管道收尾，但未覆盖极快 launcher 在赋 Job 前创建后代/退出；因此不能宣称任意 launcher 都具有进程树终止保证。

下一阶段先处理进程启动归属竞态与剩余可靠性；之后再规划批量复用。阶段进度记录自动验收、人工未覆盖项与上述限制，不把它们合并宣称为完整阶段通过。

## 每次功能开发

1. 确定本次输入、输出、范围外能力、失败行为和具体素材场景；在任务描述中写明。
2. 阅读涉及的 v1 行为与外部工具接口，确定保留行为和需要修正的缺陷。
3. 在核心模块完成本次业务流程，再接入对应桌面交互。
4. 按 [验证要求](verification.md)执行必要检查，记录实际结果和未覆盖项。
5. 满足本次验收条件后更新当前进度；功能范围改变时同步改写任务描述。

## 阶段一：最小单个封装闭环

首条验收输入：一个视频、一份 UTF-8 ASS、一个字体目录、一个独立输出目录。先固定 AssFontSubset；备用引擎、其他字幕格式和自动匹配后续增加。

```text
检查输入与工具依赖
  → 创建任务临时目录
  → 字体子集化
  → 验证修正后的 ASS 和子集字体
  → 使用这些产物封装临时 MKV
  → 校验临时成品
  → 成品落位
  → 返回结果与清理临时文件
```

- 源视频、字幕与字体保持原样；输出已存在时拒绝覆盖。
- 源字幕/附件保留策略和新增字幕轨默认值在本次任务描述中明确，成品据此校验。
- 子集化失败、字体缺失、产物不全、封装失败或校验失败时停止，不发布最终成品。
- 临时成品通过检查后才进入最终位置；落位阶段仍须防止覆盖期间新出现的目标文件。
- AFS 的 Python/fonttools 后端属于真实依赖，随首条链路验证，不因主程序使用 C# 而视为已消除。

完成条件：使用真实视频、ASS、字体和工具生成成品；核对视频、音轨、新增字幕轨、语言与旗标、字体附件，并在播放器检查字体渲染。随后在同阶段补齐简繁双字幕及对应默认轨规则。

## 阶段二：单个封装可靠性加固

单任务 UI、参数快照、取消、阶段、日志和结果已落位；后续重点是收紧工具启动与进程树生命周期边界，并补足失败路径可靠性。原生文件选择器与播放器人工项也需在交互桌面完成。

完成条件：处理 `Process.Start()` 与 Assign Job 之间的非原子窗口，验证极快 launcher 先创建后代或先退出的场景；覆盖封装失败、QC 失败、超时和取消后清理；完成原生选择器与代表性播放器的人工检查。失败或取消后源文件完整，成功结果可定位。自动化子进程用例不替代工具链或人工验收。

## 阶段三：批量复用

单个封装验收通过后添加手工任务列表和串行队列；每项都调用已经验证的单任务入口。

- 提交前计算最终输出位置并检查同名冲突。
- 默认单项失败后继续下一项；取消停止当前任务和后续调度，未开始项保留为待执行。
- 保存逐项输入快照、结果和失败原因，支持仅重跑失败项；使用原快照或修改后的参数必须明确展示。
- 第一版先完成内存队列、进度和结果汇总，再增加字幕自动匹配、持久化和重启恢复。

完成条件：真实多集成功、混合成功/失败、失败项重跑、输出冲突与中途取消均正确；单个与批量对同一输入产生一致的子集化、封装和校验行为。

## 阶段四：按实际需求扩展

单个和批量稳定后再选择预设、配置持久化、字幕自动匹配、字体体检与补给、章节、命名模板、预览、提取、修补、环境安装和发布。每项单独确定范围与验收，不要求先补齐全部 v1 功能。

涉及预设时保持单个/批量会话独立，明确字段缺失与明确留空的区别。持久化使用版本化数据、写入互斥和原子替换；真实任务恢复策略单独验证。
